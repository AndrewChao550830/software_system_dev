# Skill: cmmi_v2_engineering_task_spec

display_name: CMMI V2.0 工程研發任務規範審查

version: "1.0.0"

author: Engineering Process Team

skill_type: 工程品質審查 / 軟體研發成熟度稽核

environment: 通用軟體/系統研發專案、VSCode開發環境、敏捷/瀑布專案皆適用

description: >

依 CMMI V2.0 標準工程領域流程規範，針對「需求開發、需求管理、技術解決方案、產品整合、驗證、確認」六大核心工程任務進行全流程審查；

輸出工程活動符合度、缺陷差距、可落地改善方案與標準稽核清單；

專用於軟體研發階段Gate審查、工程品質自評、CMMI ML2/ML3 工程流程驗證。

本Skill **僅包含工程類PA，完全不包含管理類任務**，與管理Skill完全拆分、可獨立或串聯使用。

type: object

required: true

## Artifact Spec

### output_artifacts:

- cmmi_engineering_audit_report.md: 工程流程稽核總報告、各工程任務符合度、缺失總結

- cmmi_engineering_checklist.csv: 工程活動逐項稽核檢查清單（可直接導入稽核系統）

- cmmi_engineering_gap_plan.md: 工程流程差距對策與標準化改善計畫

## Gate

### pre_gate:

name: 工程稽核前置檢查 Gate

rules:

- 專案已定義目標成熟度等級與工程研發邊界範圍

- 已備齊對應工程證據：需求文件、規格、設計圖、測試案例、測試報告、整合紀錄

- 所有工程文件具備版本、日期、負責人、審核記錄

- 本Skill僅做審查與建議，不直接修改程式碼、設計、需求文件

### post_gate:

name: 工程稽核驗證 Gate

rules:

- 六大工程領域皆完成「證據查核→符合度判定→缺失描述→改善建議」

- 所有工程不符合項皆標註嚴重等級：重大/一般/觀察項

- 改善方案具體可落地、可驗證、對應CMMI工程實踐

- 輸出報告完整標示稽核時間、專案資訊、稽核範圍

## CMMI V2.0 六大標準工程領域（純工程任務）

### 1. Requirements Development 需求開發 (RD)

**任務目標**：完整挖掘、分析、定義客戶需求、產品需求、元件需求，建立可實現、可測試、一致的需求基線。

**必執行子任務**

1. 挖掘利益相關者需求：客戶、使用者、業務、營運、維護、安全等多方需求

2. 分析業務場景、使用案例、邊界條件與限制條件

3. 轉化為標準產品需求：功能需求、非功能需求（效能、安全、穩定性、相容性）

4. 拆解產品需求為次系統/模組/元件層級需求

5. 執行需求一致性、完整性、可測試性、無衝突審查

6. 建立需求層級追蹤關係：業務需求 → 產品需求 → 模組需求

7. 確認需求可被技術實現、符合成本與時程限制

8. 需求定稿後建立**需求基線**

**稽核檢查點**

- 需求來源可追溯、多方輸入完整

- 功能/非功能需求完整定義

- 需求拆解分層清晰、無模糊描述

- 需求審查會議記錄與問題閉合記錄

- 需求基線發布記錄存在

### 2. Requirements Management 需求管理 (RM)

**任務目標**：全生命週期管控需求變更、維護需求一致性、追蹤需求對工作產品的對應關係，防止需求漂移。

**必執行子任務**

1. 維護完整需求清單與版本控制

2. 建立需求追溯矩陣：需求 ↔ 設計 ↔ 程式碼 ↔ 測試案例 ↔ 交付物

3. 接收、評估、審批、控管需求變更請求

4. 分析需求變更對時程、成本、風險、品質的影響

5. 變更生效後同步更新所有關聯工程文件與工作產品

6. 定期檢查需求與實作一致性，杜絕需求漂移

7. 記錄所有需求變更歷程與理由

**稽核檢查點**

- 需求追溯表完備、無斷鏈

- 需求變更流程機制完整、有評估與審批

- 變更歷程可完整追溯

- 無私自改需求、無文件與實作不一致問題

### 3. Technical Solution 技術解決方案 (TS)

**任務目標**：依需求產生、選擇、驗證最佳技術方案，包含架構設計、詳細設計、元件實作、技術優化。

**必執行子任務**

1. 依產品需求定義系統架構、模組邊界、介面規格

2. 產生多套技術方案，進行方案評比與選擇（複雜功能須正式方案評估）

3. 完成詳細設計：模組設計、資料結構、API介面、流程圖、狀態機

4. 設計結果執行內審/交叉審查，確保符合需求、效能、安全、可維護性

5. 依設計規範進行程式實作、模組開發

6. 統一程式碼/檔案結構規範（對接PEP8/企業编码規範）

7. 技術風險納入考量：相容、擴展性、安全性、容錯性

8. 設計變更須評估影響、留存變更記錄

**稽核檢查點**

- 架構設計文件、詳細設計文件完整

- 設計完全對應需求、無額外實作、無漏實作

- 設計審查記錄齊全、問題皆閉合

- 技術方案選擇有依據、有記錄

- 程式碼結構與命名具標準性、可維護性

### 4. Product Integration 產品整合 (PI)

**任務目標**：依序整合模組、次系統、外部介面，確保最終產品完整、介面相容、功能串聯正常。

**必執行子任務**

1. 定義整合策略、整合時機、整合順序、整合層級

2. 定義模組間、系統間、第三方介面規格與介面清單

3. 執行單元模組驗證後，再進行階層式整合

4. 記錄整合過程問題、對策與修復狀態

5. 整合完成後執行整體功能串聯檢核

6. 確保整合後產品符合配置基線，版本一致

7. 交付可部署、可執行的完整產品套件

**稽核檢查點**

- 整合計畫與整合策略存在

- 介面規格清晰、介面對接無遺漏

- 整合問題追蹤與閉合記錄完整

- 最終產品版本與配置基線一致

### 5. Verification 驗證 (VER)

**任務目標**：過程驗證，確保「產品做的正確」（Do thing right），每階段產出符合階段標準與規格。

**必執行子任務**

1. 制定驗證計畫：單測、集測、介面測試、程式碼審查、設計審查

2. 依規格與設計標準開發測試案例、測試資料

3. 執行階段性驗證：設計驗證、程式碼驗證、模組驗證

4. 記錄不符合項、缺陷、測試結果

5. 缺陷修復後執行回歸驗證

6. 累積驗證證據，確保每一個工程產出皆符合設計與技術規格

**稽核檢查點**

- 驗證計畫完整、層級覆蓋全面

- 測試案例可追溯設計與技術規格

- 缺陷管理、回歸測試機制正常

- 階段驗證無遺漏、證據齊全

### 6. Validation 確認 (VAL)

**任務目標**：結果確認，確保「做對的產品」（Do right thing），最終產品符合使用者業務需求與場景。

**必執行子任務**

1. 依使用者場景、業務需求制定確認測試計畫

2. 執行使用者場景測試、功能確認、UAT使用者驗收

3. 確認產品滿足操作、維護、使用、商業目標

4. 收集使用者反饋與問題清單

5. 確認所有業務場景正常覆蓋、無場景遺漏

6. 完成產品驗收與確認結案

**稽核檢查點**

- 確認測試以業務場景為主、非只看技術功能

- UAT/使用者確認記錄完整

- 業務痛點與場景皆被滿足

- 確認結果可證明產品符合真實使用需求

## 統一輸出規則

1. 輸出【工程稽核總摘要】：專案名稱、目標成熟度、工程流程整體符合度、重大缺失數量

2. 針對上述 **RD / RM / TS / PI / VER / VAL** 六大工程領域逐項輸出：

- 工程任務核心目標

- 現場證據查核結果

- 符合度判定：符合 / 部分符合 / 不符合

- 明確缺失描述與風險說明

- 可落地改善行動與優先等級

3. 輸出【工程差距總表】依嚴重性排序

4. 輸出【工程流程標準化改善計畫】，協助團隊固化CMMI工程標準

5. dry_run=true 需標註：本報告為內部自評模擬，非正式CMMI官方評估結果

**嚴格限制**

1. 本Skill **只處理工程領域**，完全不輸出任何CMMI管理任務內容

2. 僅做審查、判定、建議，不修改任何程式碼、文件、流程配置

3. 所有判定必須「證據導向」，無證據視為未落實

## Skill Execution Steps

1. 讀取專案資訊、稽核範圍、證據路徑與執行模式

2. 依 engineering_scope 過濾並載入對應CMMI工程任務

3. 逐領域、逐子任務比對專案現況與標準差距

4. 完成符合度判定、缺失分級、改善建議

5. 產生三份標準Artifact：稽核報告、檢查清單、差距改善計畫

6. 執行Pre-Gate與Post-Gate規範驗證

7. 輸出完整可歸檔、可稽核的工程審查成果
